Drug Discovery Dashboard

A Shiny for R dashboard for exploring drug–disease–target links, clinical development, adverse events and drug risk scores. This page explains how to run it and what every function does.

Run it in VS Code

  1. Install R from cran.r-project.org.
  2. In VS Code choose File → Open Folder and open the drug-scoring folder.
  3. Press Ctrl+Shift+B, or open Terminal → New Terminal and type: 
    Rscript run_app.R
  4. The first run installs packages. When the terminal shows Listening on http://127.0.0.1:3838, the dashboard opens in your browser.
  5. To stop it, click in the terminal and press Ctrl+C.

Other tasks are under Terminal → Run Task: Rebuild data (prepare_data.R) and Deploy to shinyapps.io.

How the data flows

Raw parquet files in repo root→ prepare_data.R (run once)→ shiny_app/data/*.parquet→ app.R reads at start-up→ Sidebar filters→ Charts and tables

The app never reads the raw files. It only reads the four small tables in shiny_app/data/, so the folder is self-contained and can be deployed as it is.

The raw files repeat the same rows many times (merged_drug_data.parquet has 992,147 rows but only 9 drugs and 20 drug–disease–target links). prepare_data.R removes the repeats. This keeps memory use low and stops repeated rows from inflating report totals and link sizes.

Using the dashboard

Sidebar filters

Drugs limits every tab to the drugs you pick (leave it empty for all). Search drug name keeps drugs whose name contains the text, ignoring case; “mab” finds all the antibodies. Both filters can be used together.

Every chart card has an expand button (bottom right) for full screen. Tables can be searched and filtered per column.

Risk score

The same formula as the original Streamlit dashboard, worked out for each drug:

risk score = 0.50 × mean(LLR / max LLR)
           + 0.30 × mean(reports / max reports)
           + 0.20 × mean(stage weight) / max stage weight

LLR is the log-likelihood ratio of each adverse event (signal strength). The maximums are taken over all drugs, so a drug’s score doesn’t change when you filter.

Categories: Low (0–0.25), Moderate (0.25–0.50), High (0.50–0.75), Critical (0.75–1). This is a screening heuristic, not a validated clinical measure.

Function reference: run_app.R

A start-up script rather than a set of functions. In order, it:

  1. Checks for the packages shiny, bslib, nanoparquet, plotly and DT, and installs any that are missing from CRAN.
  2. Finds the shiny_app folder next to the script, so it works from any working directory.
  3. Starts the app with shiny::runApp() on port 3838 (or the PORT environment variable) and opens your browser. Set OPEN_BROWSER=0 to stop the browser opening.

Function reference: prepare_data.R

collapse_unique(x)

Joins the distinct, non-empty values of x into one sorted string separated by ; . Returns NA when nothing is left. Used to make one row per drug when a field has several values.

x
a vector of values for one drug

distinct_cols(df, cols)

Keeps only cols (those that exist in df) and drops duplicate rows. This is what removes the repeated rows from the raw files.

df
a data frame
cols
column names to keep

What the script does, step by step

  1. Drugs and links: reads the needed columns of merged_drug_data.parquet, builds drug_disease_targets (distinct links, with approved_symbol renamed to target) and drugs (one row per drug, using collapse_unique).
  2. Adverse events: reads adverse_clinical_combined.parquet and keeps the distinct drug × event rows.
  3. Clinical reports: the raw file repeats each drug’s reports once per adverse event, so it keeps the rows belonging to the first adverse event of each drug. This recovers the report list exactly. 16 rows with no drug name are dropped.
  4. Write: saves the four tables to shiny_app/data/ and prints their row counts and sizes.

Function reference: app.R helpers

Defined at the top of app.R. They run once when the app starts or are called by the outputs.

read_tbl(name)

Reads one parquet file from the data folder and returns a plain data frame. The data folder is found automatically: data/ when R runs inside shiny_app, or shiny_app/data/ from the project folder.

name
file name, for example "drugs.parquet"

compute_risk(ae, cl)

Calculates the risk score for each drug and returns a table sorted from highest to lowest risk with drug_name, Risk_Score, Risk_Category, Reports (sum over distinct events) and Avg_LLR. It runs once at start-up on the full data and is stored in drug_risk_all.

ae
the adverse events table
cl
the clinical reports table

count_by(x, top = Inf)

Counts how often each value appears in x, ignoring blanks and NA, and returns a data frame with label and n, most common first. Used for the pie, funnel and treemap charts.

x
a vector, for example clinical stages
top
keep only the first n values

plain(p, ...)

Gives a plotly chart the dashboard’s shared look: transparent background, the app font, tight margins and no toolbar. Extra arguments go to plotly::layout(), for example axis titles.

p
a plotly chart
...
extra layout settings

sankey(from, to, value, node_color)

Draws a two-column Sankey diagram. Each position in from, to and value is one link. Used for disease → target and drug → adverse event.

from, to
names of the left and right nodes
value
link widths
node_color
two colours: left nodes, right nodes

hierarchy(parent, child, value, type)

Draws a two-level sunburst or treemap. Parent sizes are the sum of their children.

parent, child
for example disease and target
value
size of each child
type
"sunburst" or "treemap"

table_dt(df, page = 10)

Shows a data frame as an interactive table with search, per-column filters and paging.

df
data frame to show
page
rows per page

chart_card(title, output, note = NULL, height = "420px")

UI building block: a card with a title, an optional note and a plotly chart, with a full-screen button.

output

Function reference: app.R server logic

Inside server(). Reactive values recalculate automatically when the filters change, and every chart that uses them redraws.

selected() reactive

The list of drug names that pass the sidebar filters: the drugs picked in Drugs (or all), then those whose name contains the Search text. Everything else in the app is built from this.

f_drugs(), f_links(), f_adverse(), f_clinical(), f_risk() reactive

Each of the four data tables, and the risk table, filtered to selected() drugs.

need_rows(df)

Stops an output and shows “No data for the selected drugs.” when df is empty, instead of an error.

fmt(x)

Formats a number with thousands separators, for example 1047621 → 1,047,621.

pair_counts() reactive

For the filtered links, counts how many distinct drugs connect each disease to each target. Feeds the Sankey, sunburst, treemap and heatmap on the Disease & targets tab.

ae_summary() reactive

One row per adverse event across the filtered drugs: total reports, average LLR and number of drugs, sorted by reports. Returns an empty table when no drug has adverse event data.

ae_stat(f)

Builds a value box output from ae_summary() using the function f, showing “—” when there’s no data. Used for Unique events, Total reports, Average reports and Max LLR.

current_table() reactive

The filtered table chosen on the Data tab. Shown in the preview and saved by the download button.

Update and deploy

Change the data

  1. Replace merged_drug_data.parquet and adverse_clinical_combined.parquet in the project folder.
  2. Run Terminal → Run Task → Rebuild data, or Rscript prepare_data.R.
  3. Restart the app.

Publish to shinyapps.io

  1. Once: install.packages("rsconnect"), then copy the rsconnect::setAccountInfo(...) line from shinyapps.io (Account → Tokens → Show) and run it in R.
  2. Run Terminal → Run Task → Deploy to shinyapps.io, or: 
    Rscript -e "rsconnect::deployApp('shiny_app', appName = 'drug-scoring')"

Troubleshooting

'Rscript' is not recognized

R isn’t on your PATH. Use the full path (match your R version in C:\Program Files\R\):

& "C:\Program Files\R\R-4.4.1\bin\Rscript.exe" run_app.R

To fix it permanently, add that bin folder to Path under Edit the system environment variables → Environment Variables, then restart VS Code.

Can't find the data folder

Open the whole drug-scoring folder in VS Code (File → Open Folder), not just app.R, and start with run_app.R. Check that shiny_app/data/ contains the four parquet files; if not, run prepare_data.R.

Port 3838 is already in use

An earlier copy of the app is still running. Press Ctrl+C in its terminal, or use another port: in PowerShell run $env:PORT=3839; Rscript run_app.R.

A package fails to install

Run the install yourself and read the error: Rscript -e "install.packages('plotly')". If it asks whether to install from sources, answer n.

A chart says “No data for the selected drugs.”

The filtered drugs have no records of that kind. For example, Etrolizumab has disease–target links but no adverse event or clinical report data. Clear the filters to see everything.
